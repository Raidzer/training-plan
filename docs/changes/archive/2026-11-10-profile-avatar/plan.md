# Фотография профиля с кадрированием

Статус: выполнено

Ветка: `feat/profile-avatar-upload-and-crop`

## Цель и согласование

Пользователь добавляет одно фото в собственном профиле, выбирает область и её масштаб,
сохраняет, заменяет или удаляет аватар. Сценарий согласован в чате 10 ноября 2026 года
командой «Приступай к реализации»; исходную фотографию сохранять не нужно.
Добавление production-зависимостей `react-easy-crop` и `sharp` отдельно согласовано.
Форматы и ограничения размера также подтверждены в чате.

Затронуты профиль, приватный API и хранение данных пользователей.
Актуальное поведение описано в [спецификации профиля](../../../spec/profile-avatar.md).

## Требования и критерии приёмки

- Один аватар на аккаунт. Исходник остаётся только в памяти браузера на время редактирования.
- В собственном профиле доступны выбор фото, замена и удаление; без фото показываются инициалы.
- Поддерживаются JPEG, PNG и WebP до 10 МиБ и 40 миллионов пикселей.
- В окне кадрирования фиксированы пропорции 1:1; перетаскивание и масштаб выбирают область.
  Круглая рамка показывает результат отображения аватара. Доступна клавиатура и touch.
- Отмена не меняет сохранённое фото. Повторное кадрирование требует заново выбрать исходник.
- Браузер отправляет только готовый квадратный фрагмент 512 × 512, а сервер проверяет
  содержимое и повторно кодирует в WebP без исходных метаданных. Сохранённый файл ≤200 КиБ.
- Загрузка ограничена по фактически прочитанным байтам (1 МиБ), формату, размерам
  (не более 1024 × 1024), квадратным пропорциям и числу кадров. SVG и анимация отклоняются.
- Ошибки загрузки, обработки, сети и БД понятны пользователю; прежнее фото сохраняется.
- Все операции требуют активного аккаунта; ID берётся только из сессии. Запись и удаление
  используют существующую проверку origin. Фото не доступны другим пользователям.
- Фото переживает перезапуск приложения и удаляется при удалении аккаунта.
- Интерфейс соответствует существующим токенам и Ant Design 6; touch-цели ≥44 px,
  доступные подписи, видимый фокус, состояния загрузки и ошибки, отсутствие горизонтального
  скролла на 375 px. Поддерживается системное уменьшение движения.

## Технические решения и ограничения

Отдельная таблица PostgreSQL `user_avatars`: `user_id` — PK и FK с `ON DELETE CASCADE`,
`data bytea` — готовое фото, `version` — UUID для обновления адреса изображения.
Это использует существующее постоянное хранилище и резервное копирование БД,
не добавляя синхронизацию файловой системы с транзакциями и очистку осиротевших файлов.
Бинарные данные не входят в существующие выборки пользователей и JWT.
Объём фото увеличивает размер БД и её резервных копий; отдельное файловое хранилище
можно рассмотреть при существенном росте количества пользователей.

`PUT /api/profile/avatar` принимает raw Blob и возвращает `{ version }`;
`DELETE` идемпотентно удаляет фото; `GET` возвращает WebP собственного аккаунта либо 404.
Ответы приватные, без кеширования; Next Image используется с `unoptimized`.
Метаданные версии читаются отдельно при загрузке страницы профиля.
Замена — один UPSERT; побеждает последняя выполненная операция.

Кадрирование выполняет готовый `react-easy-crop`, вывод в Blob — Canvas API.
Серверная обработка использует `sharp`. Новых глобальных тем, редактора поворота,
галереи, оригиналов, истории фото и показа фото в остальных разделах в задаче нет.

## Результаты проверок

До реализации изучены профиль, auth, удаление аккаунта, схема БД и Docker;
подтверждено отсутствие файлового хранилища.
`ui-ux-pro-max` использован для проектирования; рекомендованные им новые цвета
и шрифты не вводятся, поскольку приложение уже имеет собственную систему токенов.
Сверены документация Next.js из установленного пакета, официальные API sharp,
react-easy-crop, Ant Design и Drizzle и типы установленных пакетов.

- Миграция `0011_profile_avatar.sql` сгенерирована Drizzle. Проверка на локальном
  PostgreSQL в изолированной схеме — 6 сценариев прошли: миграции и бинарные данные,
  замена, конкурентное сохранение, повторное удаление, удаление аккаунта и гонка с ним.
- Chrome на локальном стенде с тестовым API: выбор фрагмента мышью, касанием
  и клавиатурой, масштаб, передача WebP 512 × 512, отмена, возврат фокуса,
  восстановление после ошибки, удаление, 375 px и альбомная ориентация,
  режим уменьшенного движения. Проверки прошли, ошибок JavaScript нет.
- Независимое ревью: блокирующих замечаний нет; фокус рамки перенесён на
  фактически фокусируемый элемент, настоящий редактор проверен в Chrome.
- Общий набор Vitest с покрытием: 233 файла, 1756 тестов прошли. Покрытие:
  statements 88,46%, branches 81,85%, functions 87,71%, lines 88,95%; все пороги 70% выполнены.
  В jsdom остаются диагностические сообщения об отсутствии `getComputedStyle` для псевдоэлементов.
- TypeScript (`tsc --noEmit`) прошёл. ESLint завершился без ошибок, с шестью
  предупреждениями вне новой реализации: в существующих исходниках, `coverage/` и `tmp/`.
- Production build Next.js 16.4.3 на Node 24.22.1 прошёл, включая проверку типов
  и генерацию страниц. Для запуска дочерних процессов потребовалось разрешение
  вне sandbox после `spawn EPERM`.
- В локальной Docker-БД применён только SQL `0011_profile_avatar.sql` в транзакции;
  подтверждены `bytea`, состав колонок и FK с каскадным удалением. Существующая
  история Drizzle пуста при уже созданных таблицах, поэтому общий migrator здесь
  не запускался и прежняя история не изменялась.
- Браузерная проверка использовала тестовый API; настоящий сервер проверен API-тестами
  и интеграцией PostgreSQL отдельно. Сквозной сценарий с реальной авторизацией
  и записью фото через браузер в БД не выполнялся.
- Спецификация, глоссарий и навигация обновлены. Существующие правила `.gitignore`
  для `docs/spec/` и `CONTEXT.md` сохранены; эти документы остаются локальными.
